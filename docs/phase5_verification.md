# Phase 5 — Fractures and God Hunts

Status: implementation and Prism review complete; final isolated verification evidence is recorded below. Public release acceptance remains separate.

The default client continues the actual five-act campaign into four-room Fractures and five distinct three-phase God Hunts. Core composes authored regional arenas and packs into reproducible manifests, applies all six Fracture rules, carries selected compatible elite traits into the final room, and owns finite attempts, explicit room advancement, retry, abandonment, and rewards. Tier progression unlocks the four named hunts; Nhal remains optional and requires all four primary hunts. There are no accounts, attendance gates, resets, or backend requirements.

The expedition board previews entry consumption, region, route, modifiers, counterplay, inheritance, and rewards. In combat it shows room progress, remaining attempts, death penalties, and explicit actions. Ground loot remains available until departure; the client discloses abandoned drops. Persistent rarity/discipline filters and an all-drops override affect display and pickup selection without deleting items. Ground inspection compares actual base statistics; permanent affixes are inspected after collection.

`EndgameRuntimeSession` joins campaign, active combat, immutable expedition source, permanent inventory, and reward receipts. Room and final rewards are checked against their canonical permanent receipts in both directions. Materials use the existing character wallet. Catalysts have owned/spent accounting and atomic recipe costs. Serath/Orrun grafts retain Ashcleaver's awakening and permanent-choice requirements; selected catalysts also support bounded Godwrought tempering. Character ending progress grants access; profile metadata cannot skip a new character's campaign.

Archives preserve manifests, attempts, reward identities, RNG, active effects, and replay origin. Future schemas/content are detected before typed parsing and preserved. Corrupt primary saves may recover a validated backup; imports write a new destination. The maintained Phase 4 fixture comes from the actual exported `20e1534` campaign completion, with original catalog files and byte hashes. Imported owned items, XP, materials, story, and choices are retained.

## Validation scope

It verifies overlapping replay segments every 600 commands, snapshot restoration at context changes, and final archive/profile round trips. The actual Godot client additionally exercises death/save/load/retry/abandon/recovery, attunement, all ten tiers, and all five hunts. `tools/export.sh` runs that route in the packaged application and verifies its replay independently.

Combat rules and earned character statistics were unchanged. Runtime review also introduced an explicit completed-room ledger so phantom permanent rewards cannot pass restore validation.

## Prism review and disposition

Prism (`gemini-3-flash-preview`) reviewed the complete staged phase twice and the save/navigation follow-up once. Raw reports and the reviewed patch are retained in `artifacts/phase5-review-final`.

- Removed the optional inherited-boss fallback. Nonfinal inheritance now requires the manifest's explicit candidate and rejects missing/invalid provenance without mutation. Selection caps and compatible exclusions remain deterministic.
- Fixed character/profile publication ordering: validate and merge metadata in memory, commit the character first, then publish the monotonic profile under its own writer lease. Failures before character commit cannot advance the profile. Failures afterward retain the complete character and discoveries; retry unions concurrent metadata. Regression tests cover both failure points.
- The subsequent profile-loss allegation does not apply: profile unlock/discovery metadata is also in the committed character, never the sole copy of currency or items. Load retains those discoveries; the next successful save republishes their union. Profile publication is recoverable, not a cross-file atomic transaction.
- Modal pause and missing-output-directory findings were not reproduced: actual UI checks cover pause restoration, and `AtomicFile.Write` creates parents. The reported unhandled selection-pointer read referenced a nonexistent file; the real entry point has an outer failure handler. Phase 6 additionally improves pointer recovery.
- Target iteration already sorts actor IDs and squared distance uses checked 64-bit arithmetic. Those speculative determinism/overflow findings are contradicted by the source and replay evidence.
- The existing projectile update has bounded quadratic list work (128 projectiles), and some save parsing/validation is deliberately repeated to reject unsupported nested schemas before corruption recovery. These are profiling observations, not demonstrated correctness failures. The Phase 6 synthetic 128-live-projectile update profile measures p99 0.2753 ms on this host; chained impacts and rendering are outside that narrow measurement. Full-command allocation remains explicitly measured above; no risky iteration rewrite was made merely to satisfy a speculative severity label.

## Acceptance still open

This is an engineering implementation using procedural greybox visuals and synthesized cues. Automated completion does not establish human balance, readable advanced effects on target GPUs, controller/accessibility/localization acceptance, final art/audio, or public distribution readiness. Release hardening follows in Phase 6; hardware and external playtest evidence must be recorded separately.
