# Phase 3 — Production foundation

The default client now runs `ProductionSession`, joining the actual dungeon/combat simulation with permanent character progression. Five disciplines each expose six active skills and a distinct resource loop; a curated elite echo is an additional captured ability. Core implements twelve statuses, corpse ownership, branching/chaining projectiles, bounded summons, mastery mutations, passives, ultimate gating, retraining, twelve equipment slots, six rarity contracts, six crafting services, and all four Manifestations. See `production_combat.md` and `progression_contract.md` for the numeric and transaction contracts.

Permanent item IDs, rolls, affixes, equipment, Godwrought evolution, currency, and fragment ownership have one canonical owner in `ProgressionSession`. Combat/world records are validated projections. Actual encounter clears and ability events grant experience/mastery through operation receipts. Death and travel retain progression. Cross-slot advanced-affix conflicts and two-handed/discipline restrictions are enforced by Core. Specialist rescues/research and investment unlock shared services, with proximity checks on committed operations. Extraction and grafting require explicit confirmation.

The client provides class selection, resource labels, equipment comparisons, mastery/mutation/passive choices, all crafting forms, specialist services, corpse consumption, elite echo, and charged ability release. Initial profile loading and newly selected characters share only discoveries/unlocks. English production labels support named arguments and plural forms; pseudolocalization preserves tokens and expands text for inspection. This is partial English text extraction, not a claim that the whole game is translated or every controller workflow has been manually tested.

## Saves and migrations

`ProductionSaveStore` verifies schema, rules, all content identities, checksums, and canonical/runtime agreement. Atomic character saves retain a valid backup and preserve incompatible newer files. A separately locked local profile ledger monotonically unions validated discoveries and unlocks; it carries no XP, items, or currency. The ledger may survive a subsequent failed character write. Load establishes a new replay origin after merging profile metadata.

`aw production migrate-phase2 <source> <new-destination>` supports the exact maintained Phase 2 content identities from commit `4f248d0`, at Greyhaven. It validates the original JSON checksum before introducing new typed defaults, migrates existing items/rolls/anatomy/Godwrought history, and retains unmapped permanent stash entries. The actual previous-build fixture is committed with regression coverage. Unsupported content, newer schemas, and active dungeon saves are preserved with a compatibility error; return to Greyhaven in the previous build first. Migration never overwrites its source or an existing destination. Earlier unspecified development formats are not silently treated as compatible.

## Authoring and measurements

`aw production validate|compile|demo|benchmark|replay`, `aw balance run|loot`, and `aw authoring validate|templates|pseudo` use Core. Templates preserve valid references. New ordinary enemy packs can be authored through the optional encounter registry; a test adds a pack, defeats it, restores it, and verifies its replay without a new handler. Invalid roles, references, reserved IDs, collisions, and overlapping spawns are rejected. The counted inventory and provisional art conventions are in `content_production.md`; there is no fabricated art-team production-rate estimate.

The initial full production demo completed the entire dungeon for all five fresh level-one disciplines with zero deaths, reaching level four. All five saved/replayed exactly; their 873–1,496 operations fit within the 1,800-operation archive bound. Initial full-operation p99 was 3.426 ms, including synchronization and replay hashes, excluding driver/presentation/disk IO. The initial combat reference matrix passed 25/25 class/encounter scenarios with replays. These automated policies are diagnostic and do not establish subjective balance.

The first client smoke completed five fresh opening encounters plus a full main-character route in 2,250 ticks, reaching level five, unlocking all six services, tempering permanent equipment, retraining, returning after Bell Saint, and beginning another expedition with zero deaths. Normal class selection and expanded pseudo-locale screenshots were inspected. No native input usability test is claimed.

Final exact-index verification passed all 122 .NET tests, Go checks, content/authoring validators, retained Phase 0–2 regressions, and the five-discipline production save/replay routes. The wider reference matrix passed 75/75 encounters over three seeds, and the loot run passed 20/20 encounters. An initial Veilwalker driver stall across a pillar was corrected with geometry-aware navigation; two regression cases preserve those seeds without altering game balance. The warm full-operation benchmark measured 5,833 operations, p50 0.2383 ms, p95 1.4136 ms, p99 2.4443 ms, maximum 3.9874 ms, and 363,434 allocated bytes per operation on the local Apple Silicon host. Driver, archive verification, disk, and rendering are outside that measurement.

The exact staged macOS app completed the 2,250-step production smoke and matched the editor/client replay hash `A4A3D5469945D36127418B8ED779D6E200D2E81614CA3D7F6E3921253E2A4D31`. It exercised all five opening discipline encounters and the main character's six services, level-five retraining, Bell Saint return, and second expedition. The package is ad-hoc signed, not notarized; Linux execution is configured in CI but was not run on this macOS host.

Godot 4.6.2 emitted a reproducible Android SDK editor-settings diagnostic after finishing a desktop export. The pinned engine's [Android device-poll thread](https://github.com/godotengine/godot/blob/4.6.2-stable/platform/android/export/export_plugin.cpp#L277-L438) accesses editor settings until platform teardown; this is consistent with the observed shutdown timing. `check-godot-log.py` classifies only that exact message after export completion on this pinned engine as a known diagnostic. Its raw log is retained. Tests reject the same message during client execution, before export completion, on another version, and all other errors. A successful package execution and replay remain mandatory.

## Prism review disposition

The user approved Prism's configured Gemini source-diff transmission on September 18, 2026. Two staged reviews completed (`prism-phase3.json` and `prism-phase3-final.json`). The first identified repeated equipment-stat aggregation in the progression view. Derived stats now use an immutable cache invalidated on every committed or adopted character state, with indexed item lookup during rebuilding; a regression verifies that views cannot mutate cached stats and that equip/unequip/restore update the result. The other first-pass finding cites nonexistent `Core/Actors/ActorSystems.cs`, so it has no supported execution path in this repository.

The second pass's alleged replay divergence concerns the diagnostic input policy's floating-point waypoint costs. Replays consume recorded commands and do not rerun that policy; the declared determinism guarantee uses the pinned runtime, not cross-platform bitwise input-policy equivalence. No demonstrated replay defect remains. The hub-placement finding is valid authoring debt: specialist positions remain authored in `ProductionSession.Interactions`, rather than room JSON. They are authoritative Core coordinates shared by presentation and proximity validation, so this is not a client-authority violation. Full data-driven hub placement remains an explicit production-authoring limitation.

After the cache fix, the isolated snapshot passed all 123 .NET tests, the complete verification script, and a rebuilt exported macOS app with the same production replay hash above. The repeated warm benchmark measured p50 0.2298 ms, p95 1.3306 ms, p99 2.4459 ms, maximum 4.5957 ms, and 363,376 allocated bytes per operation over 5,833 operations. The raw review reports and final logs are retained as local evidence.

Local review found that strict deserialization could mistake a future schema with new fields for corruption and fall back to an older backup. Raw version/rules/content headers now precede typed parsing in the production and retained archive readers. Regression cases preserve future outer and nested schemas, changed content, and unfamiliar fields. Character writes have an exclusive lease, and reserved profile/backup filenames cannot be used as character destinations. Malformed profile root/schema types recover through a valid backup. Review also corrected zero base stats on granted specialist rewards and fragment-derived heat/echo cleanup when anatomy changes. Real-world save I/O failures still surface to the client rather than silently starting a new character.

## Acceptance still open

This is a playable engineering prototype. Production character rigs/retargeting, final art/audio, the complete localization/accessibility matrix, independent human fun/balance testing, a staffed content budget, and release hardware certification remain open. Campaign and endgame state-contract foundations are separate future work until their combat/client integrations are delivered and reviewed. This commit does not assert a finished campaign, endgame, multiplayer expansion, season, or public launch.
