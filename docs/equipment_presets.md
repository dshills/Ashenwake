# Equipment presets

Open **Gear → Equipment presets**, choose one of eight slots, enter a name, and save the outfit currently worn. Review every slot before choosing **Equip saved set**. Replacing or deleting a saved set opens a confirmation; changing gear or switching characters invalidates it. Missing-item and compatibility explanations remain visible in the preview. See [verification](build_experimentation_verification.md).

Torren can store eight named equipment arrangements per character in Greyhaven. Saving a selected preset replaces it with the equipment currently worn. Applying it restores the entire arrangement at once, including deliberately empty slots, both ring positions, and both hands. Presets refer to the original owned item instances: later tempering, engraving, and awakening remain attached to those items.

Preset changes cost no materials and grant no items, XP, mastery, or profile unlocks. They do not change discipline, passives, selected mutations, fragments, manifestation, crafting, or inventory contents. Switching requires the same Greyhaven/Torren proximity as ordinary equipment changes; the authoritative campaign layer also requires Torren's rescue. Defeated characters cannot manage presets.

Names contain 1–32 visible characters and are unique per character without regard to case. Leading/trailing spaces are trimmed, and control/format characters are rejected. Eight fixed identities, `preset.1` through `preset.8`, avoid unbounded identity allocation. Rename and delete are separate commands; deleting a preset never destroys its equipment.

Before application, a read-only preview checks current ownership, discipline eligibility, slot/hand restrictions, and mutually exclusive affixes. Missing items and incompatible pieces are reported by equipment slot and owned-instance ID. An error leaves the entire current arrangement intact. A preset can outlive discarded or extracted equipment, retraining, or an affix change; re-saving it repairs its references to the current arrangement. No operation substitutes an item with a similar definition or recreates a missing item.

`ProgressionState.EquipmentPresets` is optional and omitted when unused or after deleting the final preset, preserving legacy snapshot hashes and content identities. Restore validates bounded, sorted preset identities, unique names, defined slots, positive historical item IDs below the character's next-item sequence, unique item placement, and known-item slot/hand compatibility. Current ownership, discipline, and cross-item affix conflicts are application checks so old presets remain available for repair. Production commands use existing atomic rollback, monotonic operation receipts, and replay records; no new save schema or catalog migration is needed.

Core APIs live in `EquipmentPresets.cs` and `ProductionEquipmentPresets.cs`. `EquipmentPresets` and `PreviewEquipmentPreset` return detached read-only collections. The production preview includes the service restriction without recording a command or receipt. Client code must additionally respect the campaign's available Torren interaction; the campaign command path enforces that rescue boundary independently.

Verification is in `EquipmentPresetTests`: atomic ring and one-/two-hand swaps, empty arrangements, replacement, discarded/extracted references, retraining, changed affix conflicts, names and capacity, idempotency, read-only projections, malformed snapshots, legacy omission, production save/replay, Torren proximity, and an earned Torren rescue followed by the outer campaign/endgame save and replay path. Test fixtures that set owned items or services are isolated from the earned rescue integration case.
