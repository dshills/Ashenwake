# Phase 6 — release engineering and recovery

Status: release engineering implemented, tested and Prism-reviewed. The exact-source local candidate passed. The procedural game is not declared a signed, independently playtested public release.

This phase connects bounded local diagnostics to the actual settings UI, clears held input on focus loss/pause/controller disconnect, requires explicit resume after reconnection, validates settings and recovers their backup, and recovers malformed/oversized character-selection pointers without deleting archives. Smoke preferences and diagnostic files stay inside the selected test output directory. Diagnostics default to excluding replay and never upload. Build identity is the loaded Core assembly MVID; packaged-source identity is recorded separately.

Maintained fixture validation freezes original bytes and executes Phase 2→3→4→5, Phase 3→4→5 and Phase 4→5 upgrades. The actual exported Phase 5 completion is now a fixture, including all ten tiers, all hunts and permanent reward receipts. Its state hash must remain unchanged on the Phase 6 load/round trip. Fixture hashes and the source package/tree provenance are retained; none of these fixtures is regenerated from a test-authored approximation.

The candidate pipeline runs the actual exported app, verifies endgame replay and release UI checks, gathers license texts from the pinned Godot engine and .NET runtime packs, and hashes the application, notices, authored content and asset sources. Its manifest lives outside the package and detects changed/missing/extra files, path traversal, symlinks and case collisions. It is an integrity record, not a publisher signature. The build remains marked `publicReleaseAccepted: false`.

## Prism review

The preliminary Phase 6 diff review reported one medium and two low findings. All three are contradicted by the implementation: `JsonData.Copy(null)` deliberately rejects null exactly as the previous `Read(Write(value))` path did, diagnostic replay is copied only under an explicit nonnull guard, and selection filenames are filtered for null before the `!` assertion. Tests cover the null and diagnostic behavior. A second staged review reported no high/medium findings and two low observations: diagnostic export checks its bounded JSON size after a temporary string allocation outside the hot path; duplicate backup-selection names are resolved by first-match selection and do not create duplicate UI entries. Neither requires a behavior change. The subsequent exported Launch router, exact-source gate and fresh package-output isolation were manually reviewed and exercised by their actual package route and eight source-gate tests. Two attempts at an additional Prism follow-up were rejected by the approval layer before transmission; the two completed Prism reports remain the phase review evidence.

## Acceptance and support boundaries

`release_readiness.md` records patch validation, backup recovery, unsupported-save handling, crash triage and candidate identity. `third_party_notices.md` records the exact notice collection process. Rendering on other OS/GPU combinations, physical controllers, long hardware sessions, human accessibility/localization/balance review, final production art/audio, project rights/credits approval, signing/notarization and a public launch decision remain open. Automated checks do not tag or publish a release, and no external services are required for single-player play.
